# Localization

Canonical reference for languages, terminology and translation quality across every Hangyul Univ product.
Source of truth in code: `packages/i18n` (`src/index.ts` `LOCALES`, `src/markets.ts` `MARKETS`,
`src/console-locales.ts`, `locales/_student_status.json`, `locales/_meta.json`).

## 1. Current status (2026-11-18)

Three different things are tracked and must never be conflated:

| Question | Answer today |
|---|---|
| **Which bundles exist?** | 56 locale bundles in `packages/i18n/locales/` (source languages: Korean = owner's source copy, English = canonical rendering and fallback). |
| **Which locales can a user actually select?** | See the table below; it is derived from code, not from this document. |
| **Who reviewed the translations?** | Machine translation plus a **synthetic (AI-model) native-level review** per locale. **No locale has had a human native-speaker review.** `HUMAN_REVIEWED` is not set anywhere. |

### Selectable locales per product

| Product | Selectable | Rule |
|---|---|---|
| Marketing (`univ.talkhangyul.com`) | the 33 market locales (`MARKETS`; Korean and English included) | every market has complete customer-critical marketing keys; URL carries `?lang=` |
| Student web + Student native | English + the 20 locales that pass the student gate: `ar bn fil hi id ja kk ko ky mn my ne ru th tr ur uz vi zh-Hans zh-Hant` | `isStudentAppLocale()`: student-journey manifest 100 % translated **and** 0 English leaks in the leak check (`_student_status.json`) |
| Operations/Admin console (`apps/agency-web`, `agency-mobile`) | **ko, en** | `CONSOLE_LOCALES` (generated by `scripts/i18n/v29/console-locales.mjs`); a console offers a language only when its namespace is complete |
| University console (`apps/university-web`, `university-mobile`) | **ko, en** | same rule |

V32 translated most console strings into every market locale, but the committed `console-locales.ts` was generated
before that and still admits only `ko` and `en`. Re-running the generator (`npm run i18n:console-locales`) decides
whether more locales are admitted; until then the selectable set above is the truth.

### Review status (what "reviewed" means here)

| Status | Meaning | Where |
|---|---|---|
| `SOURCE_APPROVED` | Source language written/approved by the product team | en, ko |
| `SYNTHETIC_REVIEWED` / `SYNTHETIC_NATIVE_REVIEWED_V32` | Machine-drafted, then reviewed by an AI model acting as a native-level reviewer (V32: five passes — meaning, naturalness, clarity, tone, back-check — against the glossary below). **Not a human review.** | all market locales; per-locale record: [`qa/v32/l10n/LANGUAGE_SIGNOFF.md`](qa/v32/l10n/LANGUAGE_SIGNOFF.md) |
| `MACHINE_DRAFT` | Machine-drafted, unreviewed; shown with "β" and a machine-translation notice | non-market bundles |
| `HUMAN_REVIEWED` | A named human reviewer, a date and a written record | **none** — open launch dependency (see [ROADMAP.md](ROADMAP.md)) |

Rules: never describe synthetic review as human review in UI, docs or marketing. `HUMAN_REVIEWED` may be set only
with a named reviewer and a dated record. Reviewer notes left for the owner (brand name in Chinese, plan terminology
in Thai/Mongolian, institution-type glosses) are listed in the sign-off file. Human review protocol:
[`research/v9-validation-protocols.md`](research/v9-validation-protocols.md) §7.

Measured in V32: 9,126 of 13,556 keys are active (`scripts/i18n/v32/census.mjs`); 3,668 are customer-critical;
48,606 strings changed across 34 locales, 38,816 of which previously had no translation.

**Launch pass, 2026-11-18 — direct-operation wording.** 166 keys that still described an external "partner agency"
were rewritten in English and Korean and re-translated in the other locales (1,820 strings, 53 locales), and the
unused partner-agency marketing subtrees were deleted. These strings are **machine-translated and were not reviewed
by the synthetic reviewer or by a human**; least confident: tg, tk, az, ps, am, ha, ig, so, yo, my, zh-Hant, fa, vi,
kk, ky, hy. The legal texts (`marketing.v12.privacy.*`, `v12.terms.*`) were not changed. Visa-route strings where
"agency" means an embassy-accredited visa agency are unchanged on purpose. The "Design Preview" entry and indicator
strings live in `packages/ui/src/design-preview.tsx` (en, ko, ja, vi, zh-Hans, zh-Hant, ru, ar; English otherwise),
not in the locale bundles.

## 2. Architecture

- **Library**: i18next + react-i18next (`packages/i18n`), shared by all web and native apps.
- **Resources**: `packages/i18n/locales/<locale>/<namespace>.json`. Namespaces: `common` (shared vocabulary — statuses, degrees, document categories, match reasons, validation, notifications), `marketing`, `student`, `agency`, `university`, `mobile`.
- **Loading**: `src/resources.ts` (generated by `packages/i18n/scripts/gen-resources.mjs`) maps each locale/namespace to a dynamic `import()`, so browsers download only the active language. English is always loaded as the fallback.
- **Fallback**: missing keys fall back to English, never to raw keys. `fallbackNS: 'common'`.
- **Locale resolution**: `?lang=` → saved preference (`localStorage hg.locale` / app settings) → browser/OS language → English. Tags such as `zh-CN`, `zh-TW`, `pt-BR`, `tl` map to supported locales (`resolveLocale`).
- **RTL**: `ar`, `fa`, `ur` set `<html dir="rtl">`; all CSS uses logical properties; directional icons flip (`.hg-flip-rtl`).
- **Formatting**: dates, numbers, currency, relative time, country names through `Intl` with the active locale (`@hangyul/utils`). Names are displayed as entered (no assumed given/family order).
- **Server-side**: notifications store `title_key` + `params` so each client renders them in the reader's language; content articles have per-locale rows with fallback to English and a `translation_status`.

## 3. Markets and country-specific behaviour

33 markets are defined in `packages/i18n/src/markets.ts` (flag, locale, URL). Flags are the owner's asset drop
(`apps/flags`), published by `scripts/media/sync-flags.mjs`. Country search matches English, native and Korean names,
ISO codes and aliases.

Nationality/issuing country is used only where operationally relevant: document legalization route, consulate-specific visa rules, required family-relationship documents, preferred language suggestion, agency language matching and localized guides. It is never used to rank or stereotype students.

## 4. Quality rules

- Copy says what Hangyul **does**; it never promises admission or a visa. No "guaranteed", no odds wording
  ("strong chance", "safe bet") for fit groups — see [ADMISSIONS.md](ADMISSIONS.md).
- One concept, one term per language (glossary, §8). Official names stay official.
- Placeholders, tags and CLDR plural families must match English; a `_one` form must carry `{{count}}` or read
  correctly without it. Korean particles after placeholders are post-processed (`을/를`, `이/가`, `은/는`, `과/와`, `으로/로`).
- University and programme names follow the reader's language (`localName()`; server side
  `server/app/core/localnames.py` via `Accept-Language`). Catalogue text that exists only in English is shown as such.
- Names are displayed as entered; dates, numbers and currency go through `Intl` with CLDR fallback chunks
  (`packages/utils/src/intl-fallback/`) for locales where Chromium's ICU is incomplete.
- The owner's Korean homepage copy is pinned verbatim (`qa/v11/koreanasha-copy.json`, `plan-content.test.ts`).

## 5. RTL

`ar`, `fa`, `ur` (and `he`, `ps` bundles) set `<html dir="rtl">`. All CSS uses logical properties; directional icons
flip (`.hg-flip-rtl`); template CSS is mirrored by postcss-rtlcss. Gradients have no logical direction — scrims and
edge masks need explicit RTL variants. `scripts/i18n/rtl-mark.mjs` adds an RLM to RTL strings that start with Latin
text or a placeholder; `unicode-bidi: plaintext` protects English fallback text inside RTL blocks.

## 6. Fallback

Missing key → English, never a raw key (`fallbackNS: 'common'`). Locale resolution: `?lang=` → saved preference →
browser/OS language → English. A product never boots into a locale it does not offer (`consoleLocale()` falls back to
ko for Korean readers, else en). When the API cannot be reached, every bundle carries the localized
service-unavailable state.

### Adding a string

1. Add the key to `en/<namespace>.json` and `ko/<namespace>.json`.
2. Use `t('<namespace>:<key>')` (or `useLocale(['<namespace>','common'])`).
3. Run `npm run i18n:check`; other locales fall back to English until translated.

## 8. Canonical glossary

One concept, one term per language. Every locale expresses each row the same way everywhere it appears: in the
marketing site, the Student app, both consoles, the native apps, e-mail and SMS. Translators and review agents work
from the **meaning** column, not from the Korean grammar: the Korean is the owner's source, the meaning is what the
service actually does ([SERVICE_CATALOG.md](SERVICE_CATALOG.md), [STATE_MAP.md](STATE_MAP.md)), and the English is the first-quality rendering
of that meaning. A foreign-language line that is grammatical but vague is a defect.

Rules that apply to every row:

- Never promise an outcome. Hangyul prepares, submits, tracks and follows up; universities admit, governments issue visas.
- Say what we **do**, not a category: "we track the dormitory application schedule" beats "dormitory support".
- Official names stay official: universities, scholarships (GKS, 국가장학금), visa categories (D-2, D-4-1), documents
  (아포스티유 = apostille, 영사확인 = consular legalization, 표준입학허가서 = standard admission letter). Add a natural
  explanation after the official term when the reader may not know it; never invent a translated institution name.
- Operational products (Agency, University) are concise and direct; the Student app is warm and simple; marketing is
  clear, aspirational and credible. Marketing copy never appears inside the consoles.

|---|---|---|---|---|
| consultation | 상담 | A scheduled conversation with the Hangyul team about the student's plan (not "counseling" in the therapeutic sense) | consultation | counseling, advising, consulting |

| deadline | 기한 | The date a Hangyul task or request is due; a university's closing date is the application deadline | due date (tasks), application deadline (universities) | deadline alone when ambiguous |
| sign in / sign up | 로그인 / 회원가입 | Account access and account creation | sign in, sign up | log in, register (except "registration" for the sign-up flow name) |
| plan | 플랜 | One of the three purchasable packages: Basic, All-in-One, Premium | plan | package, subscription, tier |
| add-on | 추가 서비스 | A priced extra proposed by the team for a specific student, approved and paid before it starts | additional service | add-on (in code and the consoles only), extra |
| service unavailable | 서비스 연결을 준비 중 | The service cannot be reached right now (no API, network down); never "error" wording | "We're getting the service ready" / "Hangyul can't be reached right now. Please try again in a moment." | failed, error 503, server |

Per-product tone, in one line each:

- **Marketing** — one idea per sentence, concrete nouns, no superlatives, no guarantees; a headline is written for the
  market, not translated from Korean word order.
- **Student** — second person, warm, one clear next step; never CRM vocabulary (pipeline, caseload, tenant).
- **Agency** — imperative, dense, operational: who, what, by when; stage names are the shared vocabulary of
  [STATE_MAP.md](STATE_MAP.md).
- **University** — formal, precise, analytical; applicants, decisions, requirements; no selling.

Plural rule (fr, ru, uk, sr, pl, cs, ar …): a `_one` form must carry `{{count}}` or read correctly without it; a string
that says "1 application" in English must not become a bare noun in the plural languages.

## Leak gate (owner requirement 7, 2026-11-20)

`npm run qa:lang-leak` (`scripts/qa/lang-leak.mjs`) renders the critical routes in Design Preview for every selectable
non-English Student locale (390 px; 1440 px for ko, ar, ja, vi), Marketing (ko, vi, ja, ar, ru) and both consoles (ko), and
fails on unintended English: runs of English words or English dictionary words in non-Latin scripts, and exact English
bundle values in Latin-script locales. The allow-list is small and explicit (Hangyul Univ, TOPIK/TOEFL/IELTS/TEPS, GKS,
IEQAS and similar acronyms, KRW/USD, file types, e-mails/URLs, names that come from data). `[data-no-l10n]` (catalogue text
quoted from a university source), `[lang=en]` exact-wording disclosures and `[data-user-content]` are excluded by design.
Last result: 0 leaks on 415 pages ([`qa/launch-final/l10n/summary.md`](qa/launch-final/l10n/summary.md)). Rules that keep it
green: university names through `uniName()`/`university_ko`, team identity through `orgName()`, server errors through
`errorText()` (code → localized message), document titles through `docTitle()`, preview fixture sentences through
`packages/api-client/src/preview/fixture-text.ts`.
