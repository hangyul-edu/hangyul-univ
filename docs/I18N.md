## Architecture

- **Library**: i18next + react-i18next (`packages/i18n`), shared by all web and native apps.
- **Resources**: `packages/i18n/locales/<locale>/<namespace>.json`. Namespaces: `common` (shared vocabulary — statuses, degrees, document categories, match reasons, validation, notifications), `marketing`, `student`, `agency`, `university`, `mobile`.
- **Loading**: `src/resources.ts` (generated by `packages/i18n/scripts/gen-resources.mjs`) maps each locale/namespace to a dynamic `import()`, so browsers download only the active language. English is always loaded as the fallback.
- **Fallback**: missing keys fall back to English, never to raw keys. `fallbackNS: 'common'`.
- **Locale resolution**: `?lang=` → saved preference (`localStorage hg.locale` / app settings) → browser/OS language → English. Tags such as `zh-CN`, `zh-TW`, `pt-BR`, `tl` map to supported locales (`resolveLocale`).
- **RTL**: `ar`, `fa`, `ur` set `<html dir="rtl">`; all CSS uses logical properties; directional icons flip (`.hg-flip-rtl`).
- **Formatting**: dates, numbers, currency, relative time, country names through `Intl` with the active locale (`@hangyul/utils`). Names are displayed as entered (no assumed given/family order).
- **Server-side**: notifications store `title_key` + `params` so each client renders them in the reader's language; content articles have per-locale rows with fallback to English and a `translation_status`.

Translation status (V8 taxonomy — see "V8 (2026-10-09)" below for the rules):

| Status | Meaning | Locales |
|---|---|---|

## Priority markets

55 countries are seeded with `is_priority_market` and a rank informed by research (Vietnam is now the largest source country, then China, Uzbekistan, Mongolia, Nepal, Myanmar…). Country search matches English, native and Korean names, ISO codes and aliases ("Burma", "Viet Nam", "UAE").

## Country-specific experience

Nationality/issuing country is used only where operationally relevant: document legalization route, consulate-specific visa rules, required family-relationship documents, preferred language suggestion, agency language matching and localized guides. It is never used to rank or stereotype students.

## Adding a string

1. Add the key to `en/<namespace>.json` and `ko/<namespace>.json`.
2. Use `t('<namespace>:<key>')` (or `useLocale(['<namespace>','common'])`).
3. Run `npm run i18n:check`; other locales fall back to English until translated.

## V8 (2026-10-09)

### Taxonomy and rules

`LocaleDef.status` (packages/i18n/src/index.ts) is one of four values:

- **SOURCE_APPROVED** — English only. All other locales fall back to it, key by key.
- **HUMAN_REVIEWED** — allowed only with real human evidence: a named reviewer, a date and a record in `docs/qa/v8/l10n/<loc>.md`. **No locale has it.** It must never be set because an AI model reviewed something.
- **SYNTHETIC_REVIEWED** — allowed only with a written record in `docs/qa/v8/l10n/<loc>.md` that names the method, persona, sample size, issues found and fixed, and residual risks, and states "synthetic review by an AI model — not a human review". It is never presented to users as a human review. In the UI (`packages/ui/src/brand.tsx`) it drops the "β" marker and the machine-draft notice, but the *partial* notice ("N % of this app is translated…") still appears for any namespace below 100 %.
- **MACHINE_DRAFT** — everything else. "β" in the picker, plus the machine-translation notice.

### Synthetic reviews (`docs/qa/v8/l10n/`)

Nine locales — **ko, vi, zh-Hans, uz, mn, ne, my, ja, th** — were reviewed on the student core flow: 416 strings each (th 218, because th has no student namespace). Each review used a student persona from that country (plus a Korean admissions officer for ko) and a six-point rubric: accuracy, naturalness, terminology per STATE_MAP, tone, truncation, honesty. Main findings, all fixed:

- **Brand:** ko used two spellings, 한귤 and 한결. 226 strings were unified to **한귤**, the canonical form in Hangyul's own Korean product (한결 is also an ordinary adverb).
- **Honesty, cross-locale:** `quick.meetsNone` had an invented promise ("but it's only temporary / not the end") in th, km, lo, uz, zh-Hant, it and ar. "Strong match" read as "strong chance" or "safe bet" (an admission-odds claim) in ru, uz, mn, my, ne, zh-Hans, zh-Hant and ja. vi `NATIONALITY_RESTRICTED` said "not open *yet*". The mn/my `emptyVerdict.reach` added "good news" and changed the meaning.
- **STATE_MAP terminology:** the quick-check "One step away" was translated as "Possible match" in vi, zh-Hans, ar, mn, my, ne and uz. The ko "Possible match" collided with the needs-grades group. "Strong" and "Not eligible yet" had 2–3 renderings each in several locales.
- **English fallbacks on core screens:** ja had 107, including the whole budget page and the machine-translation notice itself. zh-Hans, uz and mn had 14–17 each (`v4.compare.*`, verdict texts). th's notice was English.
- **Bug:** a stale `{{percent}}` in `mobile:student.nextAction.COMPLETE_PROFILE` (ja, ru, zh-Hant) — validate-locale errors, now fixed.

## V9 (2026-10-14)

### Definition of "complete for students"
A locale is **offered in the student app** only when (1) every key of the student-journey manifest (`packages/i18n/locales/_student_manifest.json` — static scan + server-sent codes + runtime recorder over ~134 routes, web 3,6xx keys / native +`mobile`) is translated, **and** (2) `scripts/qa/leak-check-v9.mjs` found 0 English leaks on ~166 page views (390 + 1440) for 10 personas. Both are recorded in `_student_status.json`; `isStudentAppLocale()` derives the picker. A synthetic review (four reader profiles × five scores, ≥ 4 each) is also recorded but does not gate. The marketing site keeps every locale. A user already on a non-gated locale keeps it, marked "Public website only".

### Pipeline
`v9-manifest` → `v9-todo <loc>` → translate (chunks) → `v9-merge <loc> <file>` (all-or-nothing validation: key in en, placeholders, tags, plural categories, brand, RTL marks) → `leak-check-v9` → synthetic review record `docs/qa/v9/l10n/<loc>.md` → `v9-coverage --record-review`. Details: `docs/qa/v9/l10n/PIPELINE.md`. `v9-sync-tier <loc…>` copies the reviewed `student:verdict` terms into `common:tier`.

### Results
See REPORT §63 for the per-locale table (manifest %, leak check, synthetic min score). **No locale is HUMAN_REVIEWED**; every record says "synthetic review by an AI model — not a human review". Human review protocol: `docs/research/v9-validation-protocols.md` §7.

### Findings worth keeping
- The same terminology bug existed in nine locales before V9: `verdict.COMPETITIVE` carried the "Strong match" term and `REACH` the "Possible match" term; legacy `common:tier.COMPETITIVE/REACH` used odds-style words ("competitive", "ambitious", "challenging"). All offered locales were corrected; English `common:tier` itself still said "Competitive match" / "Reach" and was fixed.
- Korean "Possible match" was briefly 「가능성 있음」 ("there is a chance") — an odds reading; now 「요건 충족·확인 필요」.
- Case endings glued to placeholders (mn, kk, ky, tr, ru…) were rewritten into colon/dash forms; Mongolian/Kazakh/Kyrgyz vowel harmony cannot be solved by a fixed suffix.
- Catalogue text (university summaries, seeded provider names) exists in English only; it is shown as quoted text with "published in English only" until universities provide translated copy.
- CLDR fallback data is now per-locale chunks (`intl-fallback/<loc>.ts`) loaded with that locale's translations.
